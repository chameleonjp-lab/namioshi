## 5. まとまりA: 物理・得点整合性

### 5.1 有限反射経路

反射波は、鏡像発生源だけでなく、反射した有限面と順序を保持する。命中候補を作る直前に、ビーコンから経路を逆向きにたどり、各面の区間内を正しい順で横切ることを確認する。

- 支持線だけを横切り、有限区間を通らない経路は拒否する。
- 端点は交点係数0または1の許容誤差内だけ認める。
- 2回反射は最後の面から最初の面へ逆順に検査する。
- 同じ経路で同一面を再使用しない。
- ガラス端点でも鏡像発生源はガラスの支持線で作る。

### 5.2 寿命

波が1回の更新で3秒を越える場合、実際に進める時間を残り寿命までに制限する。3秒を越えた移動、反射、得点を許可しない。移動中のビーコンも寿命時刻の位置で判定し、浮動小数の端数で次の固定stepへ波を残さない。反射は接触半径と接触時刻を求め、寿命内の接触なら子波を接触半径からstep終端まで同じstep内で処理する。処理後に寿命が尽きた親子波を残さない。

### 5.3 波の上限と表示

壁4面と反射板4面、反射深度2、同一面再使用なしから、1根波の構造上限は次になる。

```text
1 + 8 + 8 × 7 = 65波
6根波 × 65波 = 390波
```

390は性能目標ではなく、正規ルール内の経路を黙って捨てないための故障検知上限である。全品質で得点判定する波を前景に表示する。画質差は解像度、粒子、背景装飾へ使い、得点波を隠すためには使わない。

最大波数が実機で重い場合は、正しい経路を削らず、描画のまとめ方とデータ構造を改善する。

公式配置へ`(120,360)`を同時に6入力するNode診断では、同時波の実測ピークは318波だった。これは構造上限390波以内であることの確認であり、iPhone描画性能の合格を意味しない。

### 5.4 ビーコンの一時揺れ

基準位置・基準速度と、命中による一時変位・一時速度を分ける。命中は一時速度だけへ加え、上限、ばね、減衰により基準軌道へ戻す。描画中心と判定中心は同じ座標を使う。

今回の値:

| 項目 | 値 |
|---|---:|
| 命中の一時速度加算 | 22 |
| 一時速度上限 | 48 |
| 一時変位上限 | 12論理ピクセル |
| ばね係数 | 36 |
| 減衰係数 | 10 |

## 7.5 まとまりC: 有効反射弧・WebGL復旧・安全なCanvas切替

まとまりCでは、物理・得点の有限経路契約を表示とフィードバックへそろえる。反射深度がある波は、`traceReflectionPath`で各有限面を通ることを角度点列の中点で確認し、有効な区間だけを独立線分として描画する。直接波は従来どおり全円を描画する。96分割は描画サンプリングの解像度であり、物理の波数・入力数・反射数の上限ではない。

親の有限経路で到達不能な最初の仮想接触では、後続の有効な二面経路を失わないよう子波を保持する。ただし、`waveCanReach`が真になる接触だけへ反射光と`onReflect`通知を出し、無効な接触を画面・音へ公開しない。

WebGLでは`webglcontextlost`で`preventDefault()`を呼び、可視時間を精算してから入力と描画ループを一時停止する。`webglcontextrestored`ではシェーダー、プログラム、バッファを再初期化する。復帰初期化または描画中のWebGL処理が失敗した場合は、同じcanvasで2D contextを取得せず、UI属性を引き継いだ新canvasへ差し替えてCanvas 2Dへ移行する。ゲームWorld、スコア、入力キューは保持する。

ローカルではNode自動試験91件、`npm run build`、`npm run verify`、`npm run analyze:layouts`、`npm run render:layouts`、`npm run size`、`git diff --check`が成功した。自動試験は有限弧の点列、反射前の空弧、無効接触の通知抑制、WebGL復帰契約、新canvas切替、src/dist整合性を確認する。Node試験だけでは実ブラウザの強制コンテキスト消失、iPhone描画性能、長時間反復を確認済みとはしない。

まとまりCの自動確認は完了扱いとするが、Draft後のGitHub Actions、実ブラウザでの強制WebGL消失・復帰またはCanvas切替、iPhone短期確認が残る。これらを満たすまでランキングと競技版公開は停止する。

## 8. まとまりB: 時刻・入力・得点再検証

入力を「論理座標、単調増加時計の時刻、同時刻内の内部採番順」として保存し、入力時刻以上となる最初の固定境界へ到達したstepの終了後に適用する。可視中の未処理時間は捨てず、1描画3stepずつ後続描画へ持ち越す。締切は半開区間`[開始, 開始+30秒)`とし、締切をまたぐ描画では`min(now, deadline)`を供給してから同じ締切時刻で残りを精算し、accumulatorが1step未満になった時だけRESULTへ1回進む。画面休止で次の固定境界が締切後へ移った場合は、締切未満に残る受理済み入力を物理非進行の締切終端で適用してから結果を確定する。

`visibilitychange`/`pagehide`へ移る時点までの可視時間と入力は保持する。通常の復帰では固定境界と保留入力を非表示時間分だけ後ろへ移し、非表示時間を物理へ加えない。30秒締切の精算開始後に画面が隠れた場合は、締切までに積み上がった残stepを保持し、復帰後も同じ締切時刻で排出する。精算開始前に隠れて締切後に戻る場合も、境界と入力時刻を非表示開始から締切までの分だけ移し、非表示前の可視accumulatorを精算する。移動後に締切以上となる入力は破棄する。

命中帯へ入った候補はwave×beaconごとに固定step列の最小errorを保留し、帯を抜ける時、寿命最終slice、または30秒締切で一度だけ得点台帳、揺れ、onHitへ確定する。締切確定では物理を先へ進めない。完全一致だけは即時確定する。同点候補の代表は得点、反射深度、error、waveIdの順で比較し、得点差0の代表変更では副作用を出さない。

公式配置candidate-c-open-harborのfixture（137/1073/2249/3377/4193/5281ms、6入力）は20/30/60/120Hzと、可視中の50/100/150/1000msの長い描画間隔で一致した。実到達例は5481点（直接0、壁239、反射板429、2回反射4813）、台帳18件、1800固定stepであり、6480はhard ceilingとして保持するが、探索値を最大値とは断定しない。締切直前fixture `(0,110,27025ms)` は確定前358点、締切確定後589点で20/30/60/120Hzが一致した。

必須比較は20、30、60、120Hz、可視中の50/100/150/1000msの長い描画間隔、29.9秒から30.05秒の締切跨ぎ、締切精算中の画面休止、締切前に隠れて締切後に戻る場面、休止移動後も締切未満に残る受理済み入力の終端適用、`visibilitychange`と`pageshow`の二重復帰通知、29,999/30,000/30,001ms入力とする。

## 9. ランキング再開条件

次をすべて満たすまで再開しない。

1. A、B、Cが合格し、公式ルール版と理論上限を再固定する。
2. 正式URLとPublishable keyが同じプロジェクトであることを確認し、Bearerを削除する。
3. 書き込みと取得をrule、layout、seasonで分離する。
4. サーバー側でslug、整数、範囲、許可ルール、play ID一意、再送、頻度、異常隔離を検査する。
5. 競技性を主張するなら、サーバー発行のプレイ情報と入力記録の再計算を行う。行わない場合は自己申告ランキングと明示する。
6. 非本番で拒否系を確認し、ユーザー承認後に本番1件だけ疎通し、即時停止と戻し方を確認する。

本番1件の限定疎通はランキング公開や再開を意味しない。クライアントの`enabled=false`は、まとまりEの実機検収と同一候補版3回合格が終わり、ユーザーが再開を明示承認するまで維持する。

## 10. 実機停止条件

まとまりBの後、iPhone 17 Proで最低限次を確認する。

- 6入力がすべて反応し、表示される。
- 7回目だけ拒否する。
- 既知の`(0,150)`経路で説明のない反射得点が出ない。
- 得点表示と見えた波の種類が一致する。
- 3プレイ連続で操作不能、白画面、再読み込みがない。
- 最大波場面で意図しない100ms停止がない。
- 可視中の長いフレーム後も入力反応が100msを超えない。超える場合は公開を止め、追いつき方法または処理予算を見直す。
