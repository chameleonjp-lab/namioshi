# Phase 6B 画面・支援機能

## 目的

Phase 6Aで追加した結果画面を、端末の安全領域、横画面、読み上げ、フォーカス操作へ対応させる。Supabase、ランキング、物理、得点はこの工程の対象外とする。

## 画面レイアウト

CSSの安全領域変数を画面全体と重ね表示へ共通利用する。

| 対象 | 対応 |
|---|---|
| 画面 | 上下左右へsafe-areaを加えた余白を確保 |
| HUD | 上側のsafe-areaと左右のsafe-areaを加えて配置 |
| プレイ中の説明 | 下側のsafe-areaより上へ配置 |
| 初回案内 | 上下のsafe-areaを避け、狭い高さでは内部スクロール |
| 結果画面 | 縦画面では縦スクロール、横画面では内訳を4列へ変更 |
| 横画面 | 高さ600px以下でパネル幅とモードカードを調整 |

`100dvh`を使うが、内部のゲーム座標は従来どおり360×640のままとする。画面回転や表示領域の変更では、viewportと描画サイズだけを再計算する。

## 読み上げとフォーカス

- 名前入力へ見えないlabelを付け、入力補助の説明を関連付けた。
- 画面ごとに`aria-labelledby`と`aria-hidden`を同期する。
- カウントダウンはstatusとして通知し、エラーはalertとして通知する。
- 結果保存、プレイ回数、ランキング状態、共有結果をstatusとして扱う。
- ルール画面、結果画面、エラー画面、初回案内へ遷移したときに適切な要素へフォーカスする。
- `:focus-visible`で、キーボードや外部キーボードの現在位置を見失いにくくする。
- ゲーム盤面は、タップ操作が中心でキーボード操作には対応していないことをaria-labelへ明記する。

これは読み上げとフォーカスの意味づけを整える変更であり、盤面をキーボードだけで操作できることを意味しない。

## 動きを減らす設定

`prefers-reduced-motion: reduce`が有効な環境では、CSSのアニメーション、遷移、滑らかなスクロールを抑える。ゲームの制限時間、固定物理更新、得点判定は変更しない。
